# Partner integration and production readiness

## Demonstration now available
/intake supports walk-in, ambulance, elective, referral and transfer intake; unknown patients receive a temporary intake identifier without a verification prerequisite. Admin assigns a receiving clinician, who may review a synthetic referral PDF before arrival and acknowledge receipt. Crew views its own submissions, doctors their assigned intake, admissions/nurses the single demo facility. Arrival/handover is versioned and audited. Manual matching links to an existing patient record; this does not automatically create/advance a clinical encounter. The /journey clinical workflow, /remote virtual care and /paperless records/claims remain separate. Use only fictional PDFs. There is no external hospital account onboarding, actual dispatch, live ETA, automatic file transfer, or cross-facility tenancy yet.

## Partner interface requirements
- Identity: official DHA Online Verification Service, if hospital and use case are authorized; voluntary patient-present claimed-identity one-to-one verification only, liveness if approved, minimal result, manual fallback, no biometric templates stored, no face-only search. Never delay emergency treatment. DPIA, data processing contracts, privacy/security review required.
- Medical schemes: use current CMS register and certified claims switches, request scheme/administrator matrix and routes for eligibility, dependants, benefit checks, prior authorisation, claims, reversals, remittance and rejection handling. Not all registered schemes have the same interface. Official 2026 registration notice: https://www.medicalschemes.co.za/latest-publication/circular-12-of-2026-notification-of-registration-of-medical-schemes/
- Hospital exchange: identity-proofed organization accounts, care-team assignment, approved secure referral/transfer FHIR/HL7 or existing HIS interface, provenance, patient matching, acknowledgements, delivery retries and fallback secure file upload; no central unrestricted patient lookup. Agree data controller/operator roles, retention, lawful basis and emergency access policies. PDF upload requires scanning, encryption and restricted delivery in production.
- EMS: authenticated dispatch/crew assignment, pre-alert, timestamped observations and treatments, ETA updates, structured ePCR, handover acceptance. No automatic dispatch until validated.
- Labs: approved HL7/FHIR or vendor protocol, order/accession/specimen reconciliation, units and reference ranges, corrections, critical result escalation and acknowledgement, clinician reviewed release. Existing /journey lab workflow is a simulation; no provider connected.
- Imaging: approved PACS/DICOM interfaces, report review and controlled access.
- Pharmacy: validated prescription/dispensing workflow, medication safety controls and NAPPI coding, stock/reconciliation.
- Signature and telecom: approved signature method, provider terms and clinical governance; encrypted video and authorized phone/SMS integrations.
## Test matrix
Walk-in known/unknown patient; elective and referral; ambulance pickup and pre-alert; inter-hospital transfer with and without PDF; receiving clinician acknowledgement; wrong recipient denied; manual identity link; arrival and handover; laboratory specimen/results and corrected/critical result paths; electronic consent; claim accepted, rejected, corrected and partial remittance. Each external integration requires contract, sandbox credentials, negative-path testing and sign-off before live deployment. Real data must never enter public demo infrastructure.
